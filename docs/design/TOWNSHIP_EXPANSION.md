# 영구 마을과 성장 확장

상태: 1.1.0 구현·통합 검증. 2026-10-05 사용자 요청으로 시작했다. 실제 실행한 검사와 제약은 [진행 상태](../PROJECT_STATUS.md)에 기록한다.

## 사용자 요청과 유지할 방향

사용자는 Melvor Idle의 Township이 실제로 존재한다는 설명을 확인한 뒤, 우리 게임에도 Township까지 필요한 시스템을 모두 구현하라고 요청했다. 이전 제작이 너무 빠르고 대충 이루어졌다고 지적했으며, 시간이 오래 걸려도 꼼꼼한 검토를 우선한다.

마을 자동 생산을 실제 게임 기능으로 추가하는 것은 사용자 요청이다. 개별 건물·자원·수치·시설 단계와 거래 방식은 실행자 결정이다. Melvor 전체 스킬이나 수치를 복제하는 요청으로 확대하지 않는다. 주인공 한 명의 직접 활동, 성장 보존, 북방의 지역 진행, 첫 돌파의 접속 정책, 오프라인 수비와 WOS 참고 화풍을 유지한다.

마을은 지역마다 다시 짓는 야영지가 아니라 여섯 봉화와 이어지는 영구 거점이다. 지역을 옮겨도 시설·주민·창고와 진행 중인 건설을 보존한다. 주민의 생산은 주인공의 채집·제작·탐험과 독립해서 진행된다.

## 이번 제작의 완료 조건

- 영구 마을의 시설 건설·업그레이드와 미완료 건설·취소를 실제 비용과 시간에 연결한다.
- 주민·식량·연료·생산 효율과 창고 용량을 표시하고, 부족하거나 가득 찬 이유와 해결 행동을 제공한다. 장기 부재 때문에 주민이나 시설 성장이 영구 삭제되는 규칙을 만들지 않는다.
- 마을 전용 자원의 생산·사용과 주인공 가방의 물품을 구분한다. 교역·기부·보급으로 채집·제작·탐험·수비와 연결한다. 한쪽 숫자만 바뀌는 목업 거래는 허용하지 않는다.
- 시설·교역·장기 목표를 지역 돌파와 성장에 연결한다. 첫 시설을 지은 뒤 얻는 보람, 중반의 선택, 결말 뒤에도 이어지는 목표를 검증한다.
- 활동별 누적 성장과 독립 농사의 필요성을 검토하고, 채택한 기능은 입력·시간·산출·중단·복귀까지 끝까지 구현한다.
- 온라인과 오프라인에 같은 사건 루프를 사용한다. 생산·건설·보급·전투가 같은 시각에 발생하는 순서를 명시하고 긴 진행과 분할 진행의 결과가 같게 한다.
- 저장 버전과 이전 저장 변환, 잘못된 상태의 거부, 원본 보관, 복귀 요약과 중복 지급 방지까지 완성한다.
- 마을의 실제 화면과 기존 모든 메뉴를 검수한다. 모바일·키보드·주기적인 화면 갱신에서 입력·초점·펼친 정보가 유지돼야 한다.
- 새 게임에서 정규 명령으로 첫 마을 성장과 여섯 지역의 연결을 플레이한다. 준비 부족·창고 포화·자동 보급·긴 부재·재로드·중단한 건설을 별도로 검증한다.

- 화면 담당: 실제 메뉴·입력·상태·복귀 요약과 반응형 검수.

- root: 설계·계약, 저장·앱 통합, 실제 브라우저·장시간 밸런스·기존 저장 회귀와 문서.

구현 계약·데이터 값과 실제 검증 결과는 작업에 맞춰 이 문서 및 [모듈 계약](../engineering/IMPLEMENTATION_CONTRACT.md), [결정 기록](../DECISIONS.md), [진행 상태](../PROJECT_STATUS.md)에 갱신한다.

## 구현한 연결과 규칙 · 실행자 결정

마을 전용 자원 10종과 시설 12종×6단계, 교역 18종, 텃밭 4개·작물 6종, 직접 채집/제작/농사 마스터리 60종, 의뢰·장기 목표 18개를 구현했다. 씨앗 6종을 추가해 아이템은 87종이다. 새 시설 단계는 돌파한 봉화 수·마을 숙련·주민 조건을 따른다. 마을 관리가 주인공의 선택 활동이나 현재 전투를 취소하지 않는다.

마을은 60초마다 주민 식량·연료, 공장의 실제 입력, 생산 산출·공간, 세금·주민 성장·시설 상태·자동 보급을 처리한다. 새로 나온 공장 산출은 다음 생산에서 가공 입력으로 사용할 수 있다. 효율과 시설 상태로 줄어든 소수 산출은 정수 나머지로 다음 생산까지 보존한다. 상태는 80% 아래로 내려가지 않으며 재료를 소비하는 수리로 100%를 회복한다. 부족은 효율과 가공 가능 여부에 영향을 주고 영구 시설 단계나 주민을 삭제하지 않는다.

공유 창고의 자원별 배분율은 순위에 따라 12·12·11·11·10·10·9·9·8·8%다. 자원마다 공간을 확보하므로 식량 하나가 연료·공장 원료를 밀어내지 못한다. 우선순위 이동은 실제 배분을 바꾸되 기존 재고나 건설 예약분을 삭제하지 않는다. 새 보관 한도보다 많으면 추가 수용만 멈춘다. 예약한 건설 자원은 창고 공간도 점유하므로 취소는 전액 반환한다. 생산 초과분은 보관하지 못한 수량으로 기록한다. 의뢰는 비용을 낸 이후의 전체·해당 자원 공간이 보상 수량을 수용할 때만 한 번 수령할 수 있다.

식당은 식량·연료·약초를 보급품으로 가공한다. 지역과 식당 단계를 충족한 음식 교역은 실제 보급품과 주화를 사용한다. 자동 보급은 생산 시 목표 재고를 검사해 묶음 거래하며 목표보다 최대 2개 더 받을 수 있다. 높은 음식이 무한 생성되거나 잠긴 지역을 해금하지 않는다. 경비소의 전투 보너스는 각 전투 시작에 고정하고, 습격에 보존된 이전 전투는 이전 효과와 남은 시계를 복구한다.

농사는 심을 때 씨앗을 소비하고 성장 완료 때 수동 대기 또는 자동 수확·재파종을 한다. 씨앗 소진은 중단 이유를 남기며 재구입·재심기로 이어진다. 수확·제작·채집을 완료할 때 해당 활동의 마스터리만 누적된다. 실제 획득과 처치 기록은 소비 후에도 유지된다. 기존 저장의 도감은 확인 가능한 재고·생산 누계와 돌파 증거만 변환한다.

## 검토에서 고친 실제 문제

- 공유 창고를 음식이 독점해 연료·목재·약초와 모든 공장이 영구 정체되던 문제를 자원별 배분과 생산/소비 균형으로 해결했다. 시설 12종의 1단계 거점은 수리·기부·버리기·순위 변경 없이 7일 유지됨을 독립 확인했다.
- 창고 포화에서 일회성 의뢰 비용과 완료 상태만 적용되고 보상이 사라지던 문제를 수령 전 공간 검사로 고쳤다. 실패는 상태 전체를 그대로 유지하고 필요한 공간을 안내한다.
- 낮은 효율에서 매 생산 소수 산출을 버려 공장이 입력만 쓰던 문제를 저장 가능한 정수 나머지로 고쳤다.
- 오래 보존한 첫 돌파 전투의 과거 공격 시각을 손상 저장으로 오인하던 검증을 고쳤다. 보존 전투는 남은 시각을 검증하고 접속 후 같은 상대를 이어간다.
- 기존 저장에 없던 씨앗을 새 기본 도감에서 이미 획득한 것으로 처리하지 않도록 변환을 고쳤다.
- 제작 전환의 예약 재료 가용성, 펼친 설명·키보드 초점 유지, 모바일 메뉴 초점 이탈과 작은 설명의 낮은 명암을 함께 수정했다.

`tests/township-campaign.js`는 자원·능력치를 편집하지 않고 새 게임에서 정규 명령으로 여섯 지역, 모든 시설 단계와 18목표를 완료한다. 큰 경과는 같은 사건 엔진으로 계산하며 실제 사람이 그 시간 동안 접속했다는 뜻이 아니다. `scripts/verify_township.py`는 실제 버튼·입력·복귀·재로드·첫 돌파 보존·6탭의 세 화면 크기를 확인한다. 기존 전체 흐름과 모든 메뉴 회귀도 별도로 실행한다.

원작 Township의 사실·확인 시점과 우리 규칙의 차이는 [공식 자료 검토](../reference/TOWNSHIP_REFERENCE_20261005.md)를 따른다. 주민 식량·연료와 시설 유지 방식은 우리 게임의 실행자 설계이며 원작 최신 수치를 복제했다고 주장하지 않는다.
