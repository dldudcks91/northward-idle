# 북방 생존 방치 게임 기획

Melvor Idle을 참고하는 새 게임의 현재 기획이다. 캐릭터의 숙련과 장비를 발전시키면서 북방의 지역들을 차례로 탐험하고, 계속 다가오는 위협을 자동 수비로 막아낸다. 접속을 종료한 동안에도 습격과 수비가 진행되며, 돌아오면 결과를 확인한다.

현재 대화에서 합의한 방향과 실행자가 정한 세부안을 구분해 기록한다. 제작 제목은 실행자가 정한 **북방의 마지막 봉화**이며 작업 폴더는 `northward-idle`이다. 여섯 지역과 결말까지 이어지는 로컬 브라우저 게임을 제작했다. TheSevenSimulationRPG의 기존 기획과 코드를 변경하는 문서는 아니다. 논의 과정은 [대화 요약](DISCUSSION_LOG.md), 실행·플레이 방법은 [플레이 안내](../PLAY_GUIDE.md)에 있다.

## 확정한 방향

| 항목 | 현재 방향 |
|---|---|
| 게임 형태 | 생존 테마의 텍스트 중심 방치 게임. Melvor Idle의 숙련 누적과 채집·가공·보급의 연결을 참고한다. |
| 주인공과 성장 | 캐릭터 한 명의 숙련·장비·제작 능력과 야영 생활을 발전시킨다. |
| 배경 | 북방의 지역들을 차례로 탐험한다. 기본 화면의 바탕색은 파란색 계열로 한다. |
| 지역 진행 | 지역별 챕터로 진행한다. 다음 지역에 필요한 도구·장비·보급을 준비하며 성장한다. |
| 야영지 | 여정을 보여주는 배경으로 사용한다. 야영지 이사와 시설 재건을 핵심 반복 작업으로 만들지 않는다. |
| 영구 마을 | 2026-10-05 사용자 요청으로 Township 참고 마을 자동 생산을 추가했다. 주인공의 직접 활동과 독립한 생산·시설 성장을 탐험·제작·보급에 연결하며 지역 이동 때 재건하지 않는다. 세부 구현은 실행자가 정했고 [마을 확장](TOWNSHIP_EXPANSION.md)을 따른다. |
| 생존 | 음식과 장비가 탐험할 수 있는 범위와 지속 시간을 결정한다. 생존 준비와 보급을 중심으로 한다. |
| 전투 | TheSevenSimulationRPG의 Focus Stop 연출을 사용하는 자동전투와 비슷한 관전 화면을 채택한다. |
| 아트와 화면 | WOS(Whiteout Survival)의 귀여운 캐릭터와 실제 게임 UI를 참고해 모든 아트와 화면을 다시 제작한다. 둥근 입체 표현·밝은 설원·선명한 게임 버튼을 사용하며, 실제 곰 등 동물의 종별 형태와 파란색 북방 배경은 유지한다. 이전 TheSevenSimulationRPG 초상 화풍은 이번 사용자 수정 요청으로 대체한다. |
| 화면 문구 | 2026-10-05 사용자가 UI 전반의 쓸데없는 설명을 모두 제거하라고 요청했다. 소개·분위기 문장·반복 안내·구현 설명을 없애고 제목·수치·비용·조건·시간·현재 상태와 구체적 실패 이유를 중심으로 표시한다. |
| 접속 중 진행 | 탐험은 장비·제작·도감 등 다른 화면을 살펴보는 동안에도 계속 진행된다. 관전 여부가 진행 속도를 바꾸지 않는다. |
| 오프라인 탐험 | 이미 돌파한 지역의 반복 탐험은 계속된다. 새로운 지역의 첫 돌파는 접속 중에 진행한다. |
| 수비 | 위협은 접속 중과 오프라인 모두 다가온다. 자동 수비를 진행하고, 복귀하면 결과를 보여준다. |
| 작업 방식 | 기존 합의나 게임의 성격을 바꾸어 실행자가 위임 범위에서 선택할 수 없는 핵심만 사용자와 논의한다. 합의된 방향 안의 세부 설계는 실행자가 판단해 구체화한다. |
| 제작 요청 | 게임의 처음부터 끝까지 제작하고 결과를 보고한다. 시뮬레이션·화면·아트를 다중 에이전트로 병렬 제작한다. |

## 게임의 목표와 활동 연결

목표는 북방의 지역을 탐험하면서 계속 다가오는 위협을 감당할 힘을 기르는 것이다. 탐험은 새로운 자원·제작법·장비를 제공하고, 채집과 제작은 탐험과 수비에 필요한 준비를 만든다. 수비가 안정되면 다음 지역에 도전할 수 있다.

접속했을 때 플레이어는 결과를 확인하고, 장비와 보급을 개선하고, 다음 활동과 탐험 목표를 선택한다. 진행과 자동전투는 그 준비에 따라 이루어진다.

실행자가 만든 전체 여정은 흩어진 북방 마을을 잇는 봉화를 되살리는 이야기다. 여섯 지역의 마지막 위협을 차례로 돌파하면 북극광 유적의 수호자를 넘어 여섯 봉화가 다시 이어지는 결말을 확인한다. 이후에도 모든 지역의 채집·제작·반복 탐험·수비와 숙련 성장을 계속할 수 있다. 지역 수·이름·이야기·결말 후 활동은 제작 요청을 구체화한 실행자 결정이다.

## 생존과 성장 보존

합의한 기본 방향은 안전한 일상 작업과 준비가 필요한 탐험이다. 야영지의 채집·제작은 필요한 입력 재료가 떨어지면 멈춘다. 탐험은 보급을 자동 소비하고, 보급이 부족하면 귀환하는 방향으로 잡는다.

탐험 실패 시 추가 음식 최대 1개를 잃고 귀환한다. 숙련·장비·해금은 유지하며 30초 자동 회복 후 다시 활동을 선택할 수 있다. 수비 패배는 보존해 둔 활동을 30초 자동 회복 후 재개한다. 탐험 실패의 성장 보존은 기존 합의이며, 정확한 손실·회복 수치는 실행자 결정이다.

## 지역과 야영지

챕터마다 새로운 자원과 제작법이 열리고, 준비한 도구와 장비가 다음 장소의 탐험으로 이어지게 한다. 숙련·장비·작업 기능은 지역 진행에 따라 이어간다.

현재 구현한 지역은 서릿바람 해안 → 검푸른 침엽림 → 얼어붙은 호수 → 검은 이탄습지 → 칼바람 산맥 → 북극광 유적이다. 각 지역에는 채집 3개, 제작법 6개, 일반 적 2종과 마지막 위협 1종이 있다. 지역마다 다른 재료·음식·장비와 온기 조건을 사용한다. 계절이 바뀌는 달력 시스템은 이번 제작 범위에 포함하지 않았다.

이전 지역의 활동은 계속 선택할 수 있다. 지역 이동은 야영지 시설 재건이나 이사 비용을 요구하지 않고, 장비·숙련·가방을 이어간다. 한 번에 채집·제작·탐험 중 하나를 선택한다. 화면 이동은 활동을 바꾸지 않으며, 새 활동을 선택하거나 지역 이동 명령을 내릴 때만 활동이 변경된다.

## 접속과 오프라인 진행

| 활동 | 접속 중 | 오프라인 |
|---|---|---|
| 채집·제작 | 선택한 활동이 진행된다. | 선택한 활동이 진행된다. |
| 새로운 지역의 첫 돌파 | 관전 화면을 벗어나도 진행된다. | 첫 돌파 탐험은 진행하지 않는다. |
| 돌파한 지역의 반복 탐험 | 관전 화면을 벗어나도 진행된다. | 선택한 반복 탐험이 보급과 귀환 규칙에 따라 계속된다. |
| 습격과 자동 수비 | 계속 발생하고 진행된다. | 계속 발생하고 진행되며 결과를 기록한다. |
| 영구 마을·텃밭 | 직접 활동과 독립해 건설·생산·자동 보급·농사가 진행된다. | 동일한 비용·공간·씨앗·시간 규칙으로 진행된다. |

‘보고 있을 때’라는 표현은 탐험 화면을 계속 열어두어야 한다는 뜻으로 사용하지 않는다. 접속 중에는 다른 화면을 살펴봐도 탐험이 이어진다는 사용자의 설명을 기준으로 한다. 화면을 바꾸는 것과 진행할 활동을 바꾸는 것은 구분해야 한다.

새로운 지역의 첫 돌파는 접속 중에 진행하고, 이미 돌파한 지역의 반복 탐험은 오프라인에도 계속한다. 준비해 둔 활동으로 자원과 숙련을 쌓으면서 새로운 지역에 도전하는 순간은 접속 중에 경험하는 구분이다. 이전에는 제안 상태였으나, 2026-10-04 사용자가 이 방식에 동의해 확정했다. 오프라인 습격과 자동 수비도 기존 합의대로 계속 진행한다.

접속 중 관전·다른 화면·오프라인의 자동 수비는 같은 준비와 같은 경과 시간에 대해 같은 규칙으로 계산한다. 접속 종료 시 첫 돌파의 이동 진행·상대 체력·남은 공격 시간을 보존해 멈추며, 그동안 수비는 계속한다. 복귀하면 보존한 탐험을 이어간다.

실행자 결정으로 복귀 계산 상한은 7일이다. 계산한 시간과 상한 때문에 제외한 시간을 구분해서 보여준다. 결과 요약은 확인할 때까지 저장해 재접속에서도 다시 볼 수 있고, 자세한 사건은 최신 80개를 보관한다. 같은 복귀 시간을 다시 계산해 보상을 중복 지급하지 않는다.

## 전투와 관전 화면

전투 전의 무기·방어구·스킬·보급 준비가 입력이고, 시작한 전투는 자동으로 진행한다. 한 유닛이 행동할 때 다른 전투 진행을 잠깐 세우고, 앞으로 나감·타격·복귀를 보여주는 Focus Stop 방식의 박자를 채택한다.

화면은 위쪽에 적 하나, 아래쪽에 주인공을 배치하고, 새 초상·체력·행동 게이지·피해 숫자·피격 반응을 보여준다. 준비할 수 있는 태세는 균형·강타·수비 세 가지이고, 각각 네 번째 공격마다 자동 기술을 사용한다. 전투 중에는 태세·장비를 바꾸지 않는다. 음식은 탐험 조우마다 소비하며, 자동 회복을 켜두면 체력이 45% 이하일 때 주인공 행동 전에 적합한 음식을 소비해 회복한다.

기존 게임의 Stop 구현은 관전 중 정지한 만큼 실제 진행을 늦출 수 있다. 신작은 행동자의 전진·멈춤·타격·복귀 650ms 박자를 공통 전투 시간에 넣고 상대 행동 시간도 미룬다. 같은 시각에 준비된 공격은 주인공을 먼저 처리한다. 관전·동작 감소·화면 이동은 시간·보상·난수를 바꾸지 않는다. 기존 전투 엔진은 복사하지 않고 이 규칙에 맞게 새로 구현했다.

참고 위치와 확인 범위는 [참고 자료 안내](../reference/README.md)의 Focus Stop 절에 기록했다. 기존 코드와 에셋 자체는 신작에 복사하지 않았다.

## 수비의 구현 규칙 · 실행자 결정

다음은 합의한 수비 방향을 제작 요청 안에서 실행자가 정해 구현한 규칙이다. 사용자가 개별 수치를 직접 확정한 것으로 취급하지 않는다.

- 습격이 발생하면 채집 진행, 제작 예약 재료와 남은 횟수, 탐험 상대의 체력·남은 공격 시간을 보존하고 수비한다. 한 명이 탐험과 수비를 동시에 수행하지 않는다. 지역 안의 이동은 수비 전환 시 별도 이동 비용으로 계산하지 않는다. 수비가 끝나면 원래 활동과 조우를 이어간다.
- 공세의 강도는 현재 지역을 기준으로 정한다. 같은 지역에서는 준비를 갖출수록 안정적으로 버티고, 다음 지역에 진입하면 더 강한 공세를 상대한다.
- 습격 간격은 지역별 5분에서 3분 45초까지이며, 이동해도 이미 예정된 습격 시계를 초기화하지 않는다. 수비·회복 중 도착한 공세는 순서대로 처리한다.
- 패배의 손실은 음식과 일반 재료에만 둔다. 연속 패배 시작 시점의 아이템별 보유량 25%와 총 24개 중 작은 쪽을 한도로 하며, 각 패배는 보유량의 최대 8%를 잃는다. 마지막 1개와 진행 중인 제작의 예약 재료는 보호한다. 수비 승리 시 연속 손실 한도를 새로 시작한다. 숙련·장비·해금·전리품은 보존한다.
- 복귀 요약은 습격 횟수, 수비 성공과 실패, 소모한 보급, 얻은 전리품, 중단된 작업 시간을 보여준다.

원료가 부족한 제작은 이유를 표시하고 멈춘다. 중도 취소하면 예약 재료를 반환하며 완료 전 산출을 지급하지 않는다. 탐험 보급이 부족하면 자동 귀환하고, 새 활동은 플레이어가 선택한다.

## 완성한 콘텐츠와 확장 경계

현재 1.1.0 구현은 숙련 7종, 아이템 87종, 채집 18개, 제작법 36개, 지역 6개, 적 18종, 전투 태세·자동 기술 3종이다. 영구 마을은 자원 10종·시설 12종×6단계·교역 18종이고, 독립 농사는 텃밭 4개·작물 6종, 활동별 마스터리는 60종, 의뢰·장기 목표는 18개다. 마을 자체 숙련·주민·창고·세금·가공·수리와 자동 음식 보급을 주인공의 성장에 연결했다. 이 수와 단계·비용·시간은 사용자 제작 요청을 구체화한 실행자 결정이다. [콘텐츠 데이터](../../data/game.json)가 수치의 원본이며 [마을 확장](TOWNSHIP_EXPANSION.md), [플레이 안내](../PLAY_GUIDE.md)와 [진행 상태](../PROJECT_STATUS.md)에 규칙·실행·검증을 기록한다.

첫 완성본은 대표 북방 배경 1장과 인물·종별 초상 6장을 공유했다. 2026-10-04 사용자가 모든 아트와 UI를 WOS 참고로 다시 만들라고 요청해 초상 6종 전체와 서로 다른 지역 배경 6종, 컬러 SVG 30종을 새로 제작하고 8개 메뉴·전투·대화상자까지 화면 구조를 개편했다. 세부 색·구도·배치와 지역별 배경 수는 실행자 결정이다. [화면 개편 기준](VISUAL_REDESIGN.md)에 참고 출처와 구현 기준을 기록한다. 같은 종의 개체별 초상, 계정·클라우드 동기화·외부 공개 서비스는 별도 확장 범위다.

핵심 방향을 바꾸는 선택은 사용자와 다시 논의한다. 그 외 세부안은 실행자가 판단해 만들어 사용자 확정과 실행자 결정을 구분해서 기록한다. 2026-10-04 사용자는 실행자가 고를 수 없는 문제만 직접 정하겠다는 위임 범위를 재확인했다. 현재 합의 안에서 기획을 구체화하기 위해 추가로 반드시 답해야 하는 핵심 질문은 없다. 수치는 구조를 정한 뒤 데이터 표로 구체화한다.
