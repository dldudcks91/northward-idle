# Township 및 장기 성장 참고 검토

검토일 2026-10-05. 기존 Melvor 참고 사본은 수정하지 않았다. 이 파일은 현재 기획·진행 상태, 실제 구현, 기존 사본, 새로 조회한 공식 자료를 구분한다. 아래 구현 제안은 참고 규칙을 그대로 이식한 사용자 확정 사항이 아니다.

## Township에서 확인한 구조

2023 공식 패치는 Township을 다른 활동과 병행되는 시간당 자동 갱신으로 바꿨다. 수동 tick 적립, 토지 구매, 시민 사망·연령, 일꾼/직업, 매 tick 식량·석탄·옷 소비를 제거했다. 인구는 마을 XP, 행복은 인구, 교육은 생산에 연결한다. 건물은 정해진 종류와 단계로 성장하고 효율 하락에는 20% 하한이 있다. 상인은 교역소가 있으면 상시 열리며 다른 활동에 쓰는 소비형 보너스를 제공한다. 반복 의뢰는 누적 보관 후 수행하는 구조다. 이러한 연결은 자동 성장의 참고이며, 해당 숫자와 세금·종교·계절 전체가 북방 게임에 필요한 것은 아니다. [공식 패치](https://store.steampowered.com/news/posts/?enddate=1681274224&feed=steam_community_announcements)

기존 사본과 현재 코드 비교에서 주의할 차이:

- Township 자체에는 활동별 mastery가 없다. Melvor의 mastery는 개별 비전투 활동 숙련과 스킬 공용 풀을 나눈 구조이며 Township을 둘째 주인공의 능동 스킬로 만들 이유가 되지 않는다.
- 교역소의 XP 두루마리·보급품 등은 소비형 보너스다. 영구 상점 해금과 같은 것으로 표시하면 안 된다.
- 2023 패치의 건강 하락 설명과 사본의 후속 확률 설명은 시점이 다르다. 여기서 최신 유지비 수치를 확정하지 않는다.
- 2023 패치의 상인 변경과 후속 위키의 재료 상자 설명도 시간 차이가 있다. 재료 교환 가능 여부를 단일 시점으로 합치지 않는다.

## 북방 게임에서 필요한 연결

검토 시작 시 기존 게임에는 7개 스킬 XP, 채집·제작·탐험·자동 수비, 6지역과 6봉화 결말, 누적 생산/소비/손실 통계가 있었다. 활동별 mastery, 영구 마을, 건물 자동 생산, 상점, 의뢰, 실제 발견 기반 수집률은 아직 없었다. 진행 상태의 일반 명령 캠페인 검증은 결말까지 약 91분이었다. 이 수치는 해당 검증의 결과이며 모든 이용자의 플레이 시간을 뜻하지 않는다.

## 주요 허점과 검증 기준

1. 같은 시각의 작업 완료·마을 생산·농사 성숙·습격 순서를 엔진에서 고정한다. 온라인/오프라인, 한 번의 긴 계산/여러 번 나눈 계산이 같아야 한다. 마을 tick을 UI 타이머로 구현하지 않는다.
2. 7일 부재 뒤 마을을 복구 불가능하게 만드는 사망·건물 붕괴·유지비 폭탄을 피한다. 원작의 회복 가능한 효율 시스템을 참고할 수 있지만 우리의 성장 보존 규칙이 우선한다.
3. 저장 포화, 입력 부족, 업그레이드 완료, 보너스 경계, 수확, 거래까지 실제 경계를 처리한다. 평균 생산량으로 습격·고갈·해금을 통과시키지 않는다.
4. 제작 예약, 기부, 판매, 농사 씨앗 소비, 교역을 하나의 재고 규칙으로 검증한다. 한 재료를 두 번 쓰거나 예약 중인 핵심 장비를 팔지 않는다.
5. 미발견 장비·미해금 적을 요구하는 계약은 생성하지 않거나 수락 전 조건을 분명히 한다. 원작도 특정 아이템 요구 계약을 발견 이후에만 제시하도록 고쳤다. [공식 v1.2.2 변경점](https://news.melvoridle.com/game-update-v1-2-2/)
6. 수집 기록은 현재 재고를 팔아도 유지한다. 마이그레이션에서 확인할 수 있는 발견만 채우고 과거 처치/제작을 꾸며내지 않는다. 중복 보상 수령을 막고 콘텐츠 추가 시 예전 달성 보상을 회수할지 별도 정책을 둔다.
7. 준비된 후반 장비가 기존 수비에서 음식 소비를 없앤다는 현 검증을 고려한다. 마을 공급까지 추가한 뒤 재료/식량/화폐가 끝없이 쌓이는지, 채집이 무의미해지는지 여러 seed와 장기 부재로 비교한다.

## 아트 범위

기존 초상 6개·6지역 풍경은 재사용한다. 영구 마을을 읽히게 하는 둥근 3D 설원 조감 풍경 한 장을 추가하고, 작은 시설 아이콘은 기존 코드/SVG 계열로 구현하면 된다. 마을 거주자를 별도 전투 캐릭터처럼 여러 초상으로 늘릴 필요는 없다. 실제 건물 소유·레벨·작동 상태는 이미지가 아니라 코드로 표시한다. 생성·검수 파일은 [아트 기준](../design/ART_DIRECTION.md)의 영구 봉화마을 항목과 [manifest](../../assets/manifest.json)에 기록했다.
