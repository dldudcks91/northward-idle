# 작업 공간과 권한 설정

확인일: 2026-10-04. 현재 준비는 Windows의 기존 Codex 설치를 사용한다. 게임 실행 도구나 외부 앱 연결을 설치한 상태는 아니다.

## 새 폴더에서 시작

1. Codex 프로젝트 또는 편집기 작업 폴더로 `C:\Users\Semi\source\repos\northward-idle`을 연다.
2. 이 폴더를 기준으로 새 대화를 시작한다. 이전 대화의 작업 디렉터리는 문서를 작성한다고 자동 변경되지 않는다.
3. `AGENTS.md`, 현재 기획, 대화 기록, 진행 상태를 읽고 이어간다.

## 설정별 역할

| 설정 | 준비한 값 | 역할 |
|---|---|---|
| `sandbox_mode` | `workspace-write` | 현재 프로젝트 안에서 파일 작성과 로컬 명령 실행 |
| `approval_policy` | `on-request` | 허용 범위 안에서는 진행, 범위 밖 작업은 검토 |
| `approvals_reviewer` | `auto_review` | 지원되는 승인 요청을 자동 검토자가 검토 |
| `web_search` | `live` | 참고작·공식 문서의 현재 정보 검색 |
| `sandbox_workspace_write.network_access` | `false` | 셸 명령의 포괄적인 외부 네트워크 허용은 제외 |

이 값은 [.codex/config.toml](../.codex/config.toml)에 있다. 모델·추론 수준·Windows 샌드박스 선택은 기존 사용자 설정을 따른다. 다른 프로젝트를 추가 쓰기 범위에 넣지 않는다.

`AGENTS.md`와 스킬은 작업 지침이다. 실제 운영체제·앱 권한은 설정과 실행 환경이 정한다. CLI 옵션이나 조직의 강제 정책은 프로젝트 설정보다 우선할 수 있으며, 앱이 별도의 권한 프로필을 사용하면 그 범위를 따른다. 위 설정이 모든 동작을 자동 승인한다는 뜻은 아니다. [공식 설정 기준](https://developers.openai.com/codex/config-reference/)과 [설정 우선순위](https://developers.openai.com/codex/config-basic/)를 확인했다.

## 프로젝트 신뢰와 적용

Codex는 신뢰된 프로젝트의 `.codex/config.toml`을 읽는다. 이 설치에서는 사용자 설정에 새 폴더의 신뢰 항목만 추가하고 기존 설정을 보존했으며, [진행 상태](PROJECT_STATUS.md)에 백업과 검증 결과를 기록했다. 다른 컴퓨터로 옮겨 등록되지 않은 경우에는 새 폴더를 열 때 앱의 신뢰 절차를 따른다. 프로젝트 파일 안에 `trust_level`을 넣어서 스스로 신뢰를 부여하는 방식은 사용하지 않는다. [공식 설명](https://developers.openai.com/codex/config-basic/)

새 세션에서 실제 권한 표시를 확인한다. 프로젝트 설정이 읽혔는지 확인할 때에는 위 값과 비교한다. 현재 대화에서 허용된 폴더 범위가 새 폴더로 자동 교체되지는 않는다.

## 제작에 필요한 작업 범위

파일 작성·수정, 로컬 미리보기·검증, 데이터·수치 조정은 사용자 요청 범위에서 자율 진행한다. 초기 구현은 의존성이 적은 브라우저 게임으로 시작하므로 지금 Node·패키지 매니저나 원격 서비스 연결은 필수 설치 항목이 아니다.

추후 패키지 다운로드나 브라우저 자동화 도구 설치가 필요하면 구체적인 명령의 네트워크·설치 범위를 검토한다. 전역 설치나 계정 연결 대신 프로젝트 안의 도구를 우선한다. 외부 게시·배포·유료 구매 권한은 실제 해당 요청에서 다룬다.

## 프로젝트 스킬 발견

5개 스킬은 루트의 `.agents/skills`에 있다. Codex는 작업 폴더와 저장소의 이 경로에서 스킬을 발견한다. 메타데이터는 `SKILL.md`의 이름·설명과 `agents/openai.yaml`에 있으며 자동 적용을 허용한다. 새 폴더를 열어야 이 프로젝트 스킬을 사용할 수 있다. 목록에 나타나지 않으면 세션을 다시 연다. [공식 스킬 문서](https://developers.openai.com/codex/skills/)

문서와 메타데이터 점검은 `py -3 scripts/validate_workspace.py`로 실행한다. 현재 환경에서 확인한 Python은 3.13이며, 점검에는 외부 패키지를 요구하지 않는다. 게임 실행·자동화 검증 도구는 실제 구현 시 명령과 함께 추가한다.
