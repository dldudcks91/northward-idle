# 실행자 결정 기록

사용자가 확정한 핵심은 [현재 기획](design/GAME_DESIGN.md)에, 대화의 근거는 [대화 기록](design/DISCUSSION_LOG.md)에 둔다. 이 문서는 위임 범위에서 실행자가 정한 기준을 보존한다. 아래 기준을 사용자의 발언으로 취급하지 않는다.

## D-001 · 독립 작업 공간 · 2026-10-04 · 적용

사용자가 기존 저장소 옆에 새 폴더와 제작 지침·권한·스킬을 요청했다. 폴더는 `northward-idle`로 정했다. 이 기준을 세울 당시 게임 제목은 미정이었으며, 이후 D-006에서 제작 제목을 정했다. 기존 게임의 코드와 에셋은 자동 복사하지 않고, Melvor 조사 문서와 새 게임 논의만 옮긴다. 새 게임의 기획 원본은 이 폴더에서 관리한다.

## D-002 · 의존성이 적은 첫 프로토타입 · 2026-10-04 · 적용

첫 구현의 기준은 브라우저에서 실행하는 HTML/CSS/JavaScript ES 모듈이다. 시뮬레이션은 순수 JavaScript, 콘텐츠는 JSON으로 분리한다. 설치와 빌드 부담을 줄이고 경과 시간 계산을 화면과 독립적으로 검증하기 위한 선택이다. 기준 수립 당시에는 코드가 없었으나 최초 전체 게임에도 이 경계를 유지했다. 규모나 도구의 필요가 확인되면 TypeScript·프레임워크·빌드 도구를 도입할 수 있다.

## D-003 · 작업 권한 기본값 · 2026-10-04 · 적용

프로젝트 설정은 `workspace-write`, `on-request`, `auto_review`, 실시간 웹 검색을 사용한다. 새 프로젝트 안의 일반 제작 작업은 자율적으로 진행한다. 셸의 무제한 네트워크 접근과 다른 저장소의 추가 쓰기 권한은 기본값에 넣지 않는다. 필요한 명령은 실제 작업 범위에 맞게 검토한다. 기존 사용자 모델 선택과 Windows 샌드박스 설정은 유지한다. 설정 파일은 실제 앱이나 관리 정책보다 우선하지 않는다.

## D-004 · 제작 스킬의 범위 · 2026-10-04 · 적용

기획, 시뮬레이션, 화면, 검증, 아트의 5개 프로젝트 스킬을 둔다. 서로 다른 권한을 부여하는 역할이 아니라, 요청 유형별로 읽어야 할 문서와 제작·검증 절차를 안내한다. 일반 제작에 매번 확인을 요구하는 기존 프로젝트의 절차를 가져오지 않는다. 외부 앱이나 원격 저장소 연결은 지금 단계에서 설치하지 않는다.

## D-005 · 시간과 저장의 구현 기준 · 2026-10-04 · 적용

화면과 독립된 시뮬레이션이 시간·난수·보상을 소유한다. 화면은 상태와 사건을 표시한다. 같은 시작 상태와 명령 이력·난수·경과 시간은 관전 여부와 무관하게 같은 결과를 만든다. 저장에 진행 시각·난수 상태·미완료 작업을 보존하고 버전 마이그레이션을 준비한다. 이 결정은 기술 기준이며, 오프라인 탐험 범위나 수비 손실 수치를 확정하는 결정은 아니다.

## D-006 · 여섯 지역의 완결 여정 · 2026-10-04 · 적용

사용자의 처음부터 끝까지 제작 요청을 여섯 지역의 완결 여정으로 구체화했다. 제작 제목은 **북방의 마지막 봉화**, 이야기는 흩어진 북방 마을을 잇는 봉화의 회복이다. 해안·침엽림·호수·이탄습지·산맥·유적을 돌파하면 결말을 보여주고 기존 활동은 계속 선택할 수 있다. 지역별 채집 3개와 제작 6개, 아이템 81종과 숙련 7종으로 가공·장비·음식·지역 해금을 연결했다. 숫자·명칭·이야기는 실행자 결정이며 사용자 발언으로 취급하지 않는다.

## D-007 · 단일 활동과 보존된 수비 전환 · 2026-10-04 · 적용

한 명의 주인공이 채집·제작·탐험 중 하나를 수행한다. 습격 시 작업 진행과 제작 예약 재료·횟수, 탐험 상대 체력과 남은 공격 시간을 보존하고 수비로 전환한다. 지역 안의 귀환을 별도 이동 비용으로 확대하지 않는다. 수비·회복 동안 원래 활동은 진행하지 않으며 끝나면 보존한 상태를 이어간다. 예약한 제작 재료는 습격 손실에서 보호하고 취소 시 반환한다. 이 선택은 이중 활동·중복 지급과 반복 재건 부담을 막는다.

수비 패배의 손실은 일반 재료·음식에만 적용한다. 각 패배 최대 8%, 연속 패배 시작 재고의 아이템별 25%와 총 24개 한도를 함께 적용하고 마지막 1개를 보호한다. 수비 승리 시 한도를 재설정한다. 숙련·장비·해금·전리품을 보존하고 30초 뒤 회복·재개한다. 탐험 실패는 추가 음식 최대 1개 손실·귀환·30초 회복이다. 성장 보존이라는 기존 방향 안에서 실행자가 구체화했다.

## D-008 · 음식 품질과 장비·자동 기술 · 2026-10-04 · 적용

무기·방어구·부적 세 슬롯과 지역별 공격·방어·온기·전투 숙련 조건으로 준비의 효과를 만든다. 지역 음식 품질 1~6은 그 지역 이상을 요구하며, 재고 중 조건을 만족하는 가장 낮은 품질부터 사용해 높은 보급을 낭비하지 않는다. 탐험 조우마다 보급을 소비하고 회복한다. 자동 회복이 켜져 있으면 체력 45% 이하에서 주인공 행동 전에 음식을 사용한다.

균형·강타·수비 태세와 네 번째 공격마다 쓰는 자동 기술을 데이터로 관리한다. 준비 선택이므로 전투 중 변경하지 않는다. 장비 개선과 전투 숙련의 누적 효과가 다음 지역의 병목을 해결한다. 별도 수동 전술 정지나 여러 캐릭터를 추가하지 않는다.

## D-009 · 공통 전투 시계와 7일 복귀 · 2026-10-04 · 적용

전진·멈춤·타격·복귀의 650ms를 공격 주기에 포함하고 다른 행동자의 다음 공격도 같은 정지 박자만큼 미룬다. 같은 시각 사건은 회복 완료 → 주인공 공격 → 적 공격 → 작업·탐험 이동 완료 → 자연 회복 → 습격 순으로 처리한다. 상대 시계도 멈추므로 같은 화면 갱신에 두 타격이 겹쳐 마지막 사건이 지워지는 문제를 피한다. 렌더링·동작 감소와 난수·전투 결과는 독립이다.

오프라인 첫 돌파는 진행·전투를 보존해 정지하고 수비는 계속한다. 반복 탐험·채집·제작·수비는 같은 엔진으로 최대 7일을 계산한다. 긴 복귀는 5분씩 정확히 진행하고 화면 실행권을 돌려준다. 제외 시간과 실제 결과를 구분하며 최근 사건 80개를 보관한다. 24시간 비교와 7일 성능 측정에서 평균 보상을 쓸 필요가 없어 사건 계산을 유지했다.

## D-010 · 저장 원본 보존과 중복 방지 · 2026-10-04 · 적용

저장 버전 2와 전용 키를 사용하고 실제 적용 시각·난수·미완료 작업·전투·미확인 요약을 함께 보존한다. 복귀 완료 상태와 적용 시각을 한 번에 저장한다. 시계가 뒤로 가면 이전 적용 시각을 유지해 같은 시간을 다시 지급하지 않는다. v1 호환 변환, 손상·미래 버전·잘못된 ID·타이머 거부, 직전 저장과 별도 원본 보존을 구현했다. Web Locks 및 저장 변경 감지로 중복 창의 경쟁 저장을 막는다. 복구·가져오기·새 여정은 구체적인 결과를 보여주는 게임 안의 사용자 조작으로 처리한다.

## D-011 · 친구 게임 화풍의 신규 아트 · 2026-10-04 · D-013으로 대체

사용자의 화풍 지시를 실제 초상과 프롬프트를 확인한 뒤 적용했다. 굵은 윤곽·각진 면 음영·탁한 색의 새로운 주인공, 곰·늑대·멧돼지·사슴·수호자 초상과 북방 배경을 built-in image_gen으로 생성했다. 동물의 실제 종별 골격을 유지하고 기존 게임 파일은 복사하지 않았다. 초상은 512px 투명 WebP, 대표 배경은 1599×900이며 종별 개체와 지역 배경은 공유했다. 이후 D-013으로 대체했으며 이전 원본 PNG와 프롬프트·해시는 [v1 아트 목록](../assets/archive/v1/manifest.json)에 보존한다.

## D-012 · 병렬 제작과 로컬 완성본 검증 · 2026-10-04 · 적용

사용자가 명시한 다중 에이전트로 엔진·콘텐츠, 화면, 아트를 나누고 root가 앱·저장·통합·실제 브라우저·문서 검증을 맡았다. [모듈 계약](engineering/IMPLEMENTATION_CONTRACT.md)과 파일 소유권으로 충돌을 줄였다. 게임 자체는 빌드나 외부 서비스 없이 Python 표준 HTTP 서버와 브라우저로 실행한다. 선택 검증 도구만 프로젝트 내부 `.tools/python`에 설치했다. 로컬 자동 테스트와 Edge 브라우저에서 실행한 범위는 [진행 상태](PROJECT_STATUS.md)에 기록한다.

## D-013 · WOS 참고 전체 아트·게임 UI 개편 · 2026-10-04 · 적용

사용자가 이전 완성본의 모든 아트를 더 귀여운 WOS 캐릭터 참고 화풍으로 교체하고, AI 느낌이 강한 기본 UI도 WOS UI 참고로 모두 다시 만들라고 요청했다. 시간보다 명확한 수정 결과를 우선한다. WOS를 Whiteout Survival로 해석해 공식 영웅 이미지와 Google Play의 실제 탐험 선택·자동전투·월드 화면을 확인했다. 참고 출처와 해석은 [개편 기준](design/VISUAL_REDESIGN.md)에 있다.

실행자 결정으로 부드러운 3D 초상 6종과 서로 다른 지역 배경 6종을 built-in image_gen으로 새로 생성해 적용했다. 파란 바탕·북방·단일 여행자와 동물 골격은 유지한다. 이전의 어두운 윤곽·각진 음영을 대체하고, 원본과 이전 생성 기록은 보존한다. 메뉴·아이템 SVG 30종도 밝은 색과 채워진 면으로 다시 그렸다. 게임용 아트는 `assets/images/v2/`, 프롬프트·출처·알파·해시는 [현재 아트 목록](../assets/manifest.json)에 있다.

동일 카드와 중복 안내가 반복되는 세 열 대시보드를 큰 지역 장면·주인공·짧은 수치 HUD·입체 버튼으로 바꿨다. 8개 메뉴·전투·모달·복귀·시작 및 복구 화면을 함께 개편했다. 저장 키·형식·콘텐츠 ID·시뮬레이션 규칙은 유지해 기존 여정을 그대로 이어간다. 다중 에이전트가 초상·지역 배경·화면을 분담하고 root가 실제 사용 흐름·전체 메뉴·반응형·구 저장 호환을 검증했다. 상세 검증 결과는 [진행 상태](PROJECT_STATUS.md)에 기록한다.

## D-014 · 영구 마을과 방치 가능한 생산 연결 · 2026-10-05 · 적용

사용자는 Township까지 필요한 시스템을 실제로 구현하고 빠른 제작보다 꼼꼼한 검토를 우선하라고 요청했다. 그 요청 안에서 1.1.0의 마을 자원 10종·시설 12종×6단계·교역 18종, 텃밭 4개·작물 6종, 활동별 마스터리 60종과 의뢰·장기 목표 18개를 실행자가 구체화했다. 주인공 한 명의 직접 활동과 독립한 주민·농사를 연결하고, 지역 돌파로 시설과 음식 품질을 단계적으로 연다. 지역 이동 때 재건하지 않는다. 확인한 Melvor 공식 자료의 시점·한계와 신작 설계는 [검토 기록](reference/TOWNSHIP_REFERENCE_20261005.md)에 구분한다.

공유 창고만 사용한 초안은 음식 포화가 연료·원료를 밀어내 모든 공장을 정체시켰고, 매분 기부하는 검증 플레이가 필요했다. 독립 감사와 실제 장시간 진행에서 이를 확인해 순위별 자원 보관 공간·상태 하한80%·기초 생산과 가공 입력의 균형을 적용했다. 정수 소수 산출을 누적 보존하고 의뢰 수령 전에 비용 후 보상 공간을 검사한다. 기부·버리기·수리는 선택 관리 수단으로 남긴다. 자동 음식 보급은 실제 자원·코인을 소비하며 묶음 단위로 목표를 충족한다. 정규 완주는 관리 명령197개와 9.56게임시간에 12시설 최종단계·18목표를 완료했고, 독립 1단계 거점은 7일간 관리0회로 유지됐다.

공통 사건 순서에 건설·마을·농사를 기존 전투보다 먼저 넣고, 전투 시작에 마을 효과를 고정한다. 저장 버전3으로 확장하되 v2키를 유지하여 기존 여정을 발견한다. 검사값을 변환 전에 확인하고 이전 활동·예약·전투·난수·적용 시각을 보존하며 새 거점은 기존 저장 시점부터 시작한다. 소급 마을 보상과 존재하지 않던 씨앗 발견·처치 기록을 만들지 않는다. 긴 첫 돌파 보존 전투의 과거 절대 시각은 남은 타이머와 구분해 검증한다. 이전 D-009/D-010의 공통 시간·원본 보존 방향을 이어가는 확장이다.

마을 6탭을 추가하고 실제 비용·가용성·시간·도감·복귀 요약을 순수 엔진 API로 표시했다. WOS 참고 신규 마을 풍경을 built-in image_gen으로 생성하고 기존 초상·지역 배경은 보존했다. 파일 소유권을 나눈 다중 에이전트 구현과 독립 감사를 수행했다. 결과·버그 수정·재현 명령·제약은 [확장 규칙](design/TOWNSHIP_EXPANSION.md)과 [진행 상태](PROJECT_STATUS.md)에 기록한다.

## D-015 · 행동과 수치 중심의 화면 문구 · 2026-10-05 · 적용

사용자가 UI 전반의 쓸데없는 설명을 모두 제거하라고 요청했다. 소개 배너·분위기 문장·영문 장식 제목·반복 안내·성공 메시지·데이터 설명 툴팁을 DOM에서 삭제하고 빈 여백도 줄였다. 기본 화면에는 제목·수치·시간·비용·조건·상태·입력·버튼과 구체적인 실패 이유를 남긴다. 보급 품질/가격·씨앗 재고·회복 임계 체력·예약 반환·저장 교체와 초기화의 결과는 짧게 표시한다.

복귀의 상세 사건은 기록 메뉴와 중복되어 제거했다. 기록은 표시 전용으로 story/guide를 제외하고 이동·돌파·해금·결말 등을 축약한다. 원본 사건 배열·시뮬레이션·콘텐츠·저장은 변경하지 않는다. 삭제한 제작 설명의 펼침 검사만 기존 브라우저 도구에서 제거하며 기능·입력·초점·복귀·모바일 검사는 유지한다. 실제 검수 결과는 [진행 상태](PROJECT_STATUS.md)에 기록한다.

## 이후 기록 방식

의미 있는 선택마다 식별자, 날짜, 상태, 이유와 영향을 짧게 추가한다. 기존 결정을 바꾸면 이전 항목을 대체됨으로 표시하고 새 항목을 연결한다. 폰트 크기나 변수명처럼 영향이 작은 모든 선택을 기록하지 않는다.
