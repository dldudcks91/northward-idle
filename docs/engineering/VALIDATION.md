# 검증 기준

실제로 실행한 명령·조건·결과를 [진행 상태](../PROJECT_STATUS.md)에 요약하고, 재현 자료는 필요한 경우 작업 산출물로 남긴다. 이 문서는 현재 검증 기준이며 모든 미래 조건이 이미 통과했다는 뜻이 아니다.

## 시뮬레이션의 핵심 비교

같은 시작 상태·데이터·난수 상태·명령 이력으로 같은 종료 시각까지 계산한다. 관전·다른 화면·숨겨진 탭·복귀 계산을 비교한다. 오프라인 활동 정책이 다르면 허용된 활동끼리 비교하고, 정책 차이를 엔진 오류로 취급하지 않는다. 오프라인 수비는 온라인과 같은 규칙이어야 한다.

한 번의 긴 진행과 같은 시간을 여러 구간으로 나눈 진행의 최종 상태·경제·난수·처리한 사건을 비교한다. 공격이나 제작 완료의 직전·정확한 경계·직후, 습격과 보급 소진이 겹치는 시각을 포함한다. 사건 보관 상한에 따른 표시 차이는 실제 상태 차이와 구분한다.

## 변경 종류별 최소 검증

| 변경 | 확인해야 할 실제 성질 |
|---|---|
| 활동·제작 | 정확한 재료 소비와 산출, 부족할 때 중단, 중단·재개 후 중복 지급 없음 |
| 탐험·귀환 | 자동 보급 소비, 소진 경계, 허용된 손실, 귀환과 다음 활동의 상태 전이 |
| 습격·수비 | 온라인·오프라인 발생, 중단·재개, 승패·손실·누적 한도, 장기 부재에도 성장 보존 |
| 자동전투 | 같은 난수에서 같은 승패·시간·보상, Focus Stop 관전 여부로 차이 없음 |
| 저장·복귀 | 재로드와 마이그레이션, 손상·미래 버전 보존, 복귀 결과 중복 적용 없음 |
| 시계·긴 계산 | 음수·중복 경과 없음, 미래 시각 저장의 처리, 긴 부재 계산의 완료와 응답성 |
| UI·연출 | 실제 브라우저 조작, 다른 화면에서 지속 진행, 읽을 수 있는 복귀 요약, 축소 화면·키보드·동작 감소 |
| 밸런스 데이터 | ID와 참조·해금 유효성, 비용·산출 일관성, 실제 성장 병목과 수비 준비의 효과 |
| 마을·농사 | 건설 예약/환불과 순서, 자원별 공간/포화/보상 보존, 업스트림 수급, 소수 산출, 유한 씨앗, 자동 보급의 실제 비용 |
| 마스터리·도감·의뢰 | 실제 완료/획득/처치에만 성장·기록, 정수 보너스 보존, 납품 비용과 한 번 수령, 변환 시 없는 과거 기록을 만들지 않음 |

## 밸런스 측정

첫 지역에서 필요한 준비 시간, 음식의 생산과 소비, 장비 개선 전후 수비 결과, 다음 지역 진입에 필요한 선택을 측정한다. 시간·자원·수비 손실이 서로 연결되는지 실제 시나리오로 판단한다.

무작위 승률을 논할 때는 여러 고정 시드와 표본 수·편차를 함께 기록한다. 단 한 번의 승리로 안정적인 방치를 주장하지 않는다. 수치는 참고작에서 복사하지 않고 이 게임의 체감 목표를 위해 조정한다.

## 작업 공간 점검

전체 게임 1.0의 자동 검증은 `python scripts/test.py`로 Node 내장 테스트를 실행한다. `tests/campaign.js`는 새 상태를 편집하지 않고 정규 명령만으로 재료·장비·보급을 준비해 여섯 지역을 돌파하는 플레이어다. 시간만 같은 엔진으로 진행하므로 실제 사람이 같은 시간 동안 접속해 플레이했다는 결과와 구분한다.

`python scripts/verify_browser.py`는 로컬 서버와 설치된 Edge를 사용해 실제 버튼·입력·설정·저장·메뉴·전투·모바일·복귀·복구를 검증한다. 출력은 `artifacts/browser/report.json`과 JPEG 화면이다. 타이머 정지 복구는 Chromium의 실제 lifecycle freeze/active로 확인한다. 재로드 중복 검증은 브라우저 경계의 실제 시각을 고정해 합법적인 추가 경과와 중복 계산을 구분한다. 결말은 정규 명령 시나리오로 만든 상태를 실제 UI에 적용해 확인한다.

전체 아트·UI 개편은 `python scripts/verify_visual_redesign.py`로 새 초상·지역별 배경의 실제 이미지 해석, 여섯 지역의 화면 적용, 8개 메뉴의 1440·768·390px 가로 넘침, 개편 전 내보낸 실제 v2 저장의 자원·장비·숙련·난수·미완료 필드 보존과 결말 표시를 추가 확인한다. 같은 재료가 여러 제작법에 표시될 때 갱신 뒤 초점이 원래 카드에 남는지, 채집 중 발생한 수비의 관전 버튼이 실제 전투와 현재 지역 배경을 여는지도 검증한다. 저장 표본은 이전 브라우저 검증에서 내보낸 파일이며 사용자 브라우저의 실제 저장을 읽거나 수정하지 않는다. 출력은 `artifacts/redesign/report.json`과 메뉴·지역별 JPEG다. 자동 검사만으로 화풍이나 화면 완성도를 판정하지 않고 실제 스크린샷도 열어 확인한다.

1.1.0에서는 위 전체 화면 검사를 마을 포함 9메뉴·고유 아트13개로 확대한다. `scripts/verify_township.py`는 실제 건설·취소·완공·교역 횟수·씨앗 소비·수동 수확·납품/한 번 보상·보급 설정·창고 순위·입력/초점 유지, 6탭×1440/768/390px, 경험치 문구의 패널 경계/글자 잘림과 모바일 초점 제한을 확인한다. 실제 앱의 2시간 분할 복귀를 순수 엔진의 전체 상태와 비교하고 재로드·요약 확인·마을 이동을 검증한다. 1시간 첫 돌파 보존 전투도 복귀·재로드·재개하며 불량 복귀 사건 목록은 저장 복구 안내와 원본 보존을 확인한다. 결과는 `artifacts/township/browser/report.json`과 용량을 줄인 JPEG 화면이다. 2026-10-05 문구 정리에서 제작 설명 DOM을 삭제했으므로 그 설명의 펼침 유지를 검사하던 항목도 제거했다. 게임 기능과 입력·초점 검사는 유지한다.

`tests/township-campaign.js`의 정규 플레이는 자원이나 능력치 편집 없이 세 시드로 여섯 지역과 12시설의 최종단계·18목표를 완료한다. `tests/township-integration.test.js`는 마을·농사·마스터리 요약의 5분 분할 일치, 정규 완주 거점의 7일 성장 보존, 열 개 고정 난수에서 마지막 지역 자동 보급의 비용과 24시간 반복 탐험 효과를 측정한다. 난수 비교는 정규 완주 상태의 난수만 바꾸는 통제 실험이며 별도 실제 새 게임 완주와 구분한다. 결과는 `artifacts/township/campaign.json`, `supply-balance.json`이다.

`tests/expansion.test.js`는 경계 전용 상태를 명시해 건설·생산·공격의 동시 사건, 예약 공간과 전액 환불, 단계별 비용/자원 한도/업스트림 유지, 정수 소수 산출, 자동 보급 묶음·비용, 씨앗 소진·재개, 보상 공간·한 번 수령, 전투 효과 고정과 보존 전투 복구를 검사한다. `tests/storage.test.js`는 이전 v2의 7상태 원본을 먼저 검증해 변환·진행 보존과 긴 보존 전투의 재로드를 확인한다. 경계 시험용 재고·체력을 편집한 상태를 정규 완주의 증거로 사용하지 않는다.

의존성 설치와 실행 명령은 [README](../../README.md)에 있다. 아트 원본·투명도·파생본 검수는 [아트 기준](../design/ART_DIRECTION.md)을 따른다.

현재 실행 가능한 준비 단계의 점검은 다음 명령이다. Python 3.11 이상이며 외부 패키지가 필요 없다.

```powershell
py -3 scripts/validate_workspace.py
```

필수 파일, UTF-8, 내부 문서 링크, 제한된 스킬 YAML 형식, 스킬 이름·설명·선택 UI 메타데이터, 프로젝트 TOML, 참고 문서 사본 수와 출처 기록의 해시를 검사한다. 모든 형태의 YAML을 해석하는 범용 도구는 아니다. 새 메타데이터 구조가 필요하면 검사기를 함께 확장하거나 정식 YAML 검사기를 사용한다.
