# 구현 기준

상태: 마을 확장을 포함한 1.1.0의 구현 기준. 게임의 확정 방향은 [현재 기획](../design/GAME_DESIGN.md), 선택 근거는 [결정 기록](../DECISIONS.md)을 따른다.

## 첫 구현의 기술 선택

브라우저용 HTML/CSS/JavaScript ES 모듈로 시작한다. 시뮬레이션과 콘텐츠를 화면에서 분리한다. 첫 프로토타입에는 계정·서버·클라우드 저장이 필요하지 않다. 도구가 필요한 근거가 생기면 빌드 도구나 프레임워크를 도입하고 실행·검증 명령을 README에 기록한다.

실제 구현의 경계는 다음과 같다. 모듈의 함수·콘텐츠 계약은 [구현 계약](IMPLEMENTATION_CONTRACT.md)에 있다.

전체 아트·UI 개편은 이 경계를 유지한다. `assets/manifest.json`의 안정적인 에셋 ID를 실제 v2 파일 경로로 연결하고, 지역 배경은 `region-<지역 ID>`를 사용한다. 표시 이름·CSS·뷰 구도는 저장 상태의 원본이 아니므로 저장 버전 2·전용 키·콘텐츠 ID·시간과 난수·미완료 활동은 그대로 이어간다. 앱의 시작·중복 창·복구 대화 상자도 공통 게임 스타일 클래스를 사용한다.

| 영역 | 구현 위치 | 책임 |
|---|---|---|
| 시뮬레이션 | `src/simulation/` | 경과 시간, 전투·수비·활동, 자원·성장, 사건 |
| 앱 제어 | `src/app/` | 명령, 시계 연결, 복귀 계산, 저장 연동 |
| 저장 | `src/storage/` | 직렬화, 버전, 검증, 마이그레이션, 백업 |
| 화면 | `src/ui/` | 상태 표시, 입력 전달, 전투 사건 연출 |
| 콘텐츠 | `data/` | 식별자가 안정적인 JSON 자원·레시피·지역·적·설정 |
| 에셋 | `assets/` | 원본·파생 이미지와 출처 기록 |
| 로직 검증 | `tests/` | 시간·난수·경제·전투·저장 회귀 |

## 시간과 난수

시뮬레이션은 시간과 난수 상태를 입력으로 받아 결과 상태와 사건을 만든다. 로직 안에서 DOM, 브라우저 저장소, 전역 현재 시각, 전역 난수를 직접 읽지 않는다. 실제 시각과 난수 초기값은 앱 경계에서 제공한다.

접속 중·숨겨진 탭·오프라인 복귀는 같은 경과 시간 계산을 호출한다. 활성 화면의 `requestAnimationFrame`이나 애니메이션 종료 콜백이 전투 공격·보상 지급·다음 습격 시각을 결정하지 않는다. Focus Stop의 정지 박자를 전투 시간에 넣는다면 모든 실행 경로에서 동일하게 계산한다.

시간 단위는 밀리초를 기준으로 통일하고, 같은 시각에 발생한 작업 완료·공격·보급 소진·습격의 처리 순서를 명시한다. 큰 구간으로 진행한 결과와 나누어 진행한 결과가 일치하도록 미완료 시간과 사건 순서를 보존한다. 실제 성능을 측정하기 전에 평균 승률·평균 보상으로 계산을 대체하지 않는다.

난수 상태·대기 사건·작업의 남은 시간은 저장 가능한 값이어야 한다. 장기 계산을 나눠 실행할 때 중간 상태와 계산 종료 시각을 보존하고, UI 응답을 유지한다. 재개 시 마지막으로 적용한 사건을 다시 지급하지 않는다.

## 활동과 수비

다음 개념을 모델에 구분한다: 선택한 활동, 실제 진행 단계, 수비를 위해 중단한 활동, 회복 단계, 다음 습격, 현재 보급과 장비. 활동의 동시 진행 개수와 수비 중단·복귀 규칙은 설계 상태를 확인한 뒤 데이터와 전이로 표현한다.

이벤트 경계에서 자원이 음수가 되지 않게 하고, 재료 부족·보급 소진·귀환·전투 종료·수비 결과의 적용을 한 번만 수행한다. 한 명의 주인공이 탐험과 수비에서 동시에 존재하는 모순은 구현 전에 해결해야 한다. 해결안은 사용자 확정과 실행자 제안을 구분해 기록한다.

시간을 뒤로 돌린 경우 진행을 음수로 계산하지 않는다. 처리한 저장 시각을 되돌려 같은 시간을 다음 실행에서 다시 계산하지 않도록 정한다. 장기간 부재의 상한·손실 한도·사건 보관량은 게임 설계로 결정하며 기술 문서에서 임의의 수치를 확정하지 않는다.

## 데이터와 저장

현재 콘텐츠 원본은 `data/game.json`, 엔진은 `src/simulation/engine.js`, 앱은 `src/app/main.js`, 저장은 `src/storage/save.js`, 화면은 `src/ui/view.js`다. 앱이 JSON을 검증하고 같은 객체를 엔진과 화면에 제공한다. Python 표준 HTTP 서버는 파일을 제공할 뿐 진행과 저장은 브라우저에서 이루어진다.

활동·아이템·레시피·지역·적은 표시 이름과 분리된 안정적인 ID를 갖는다. 참조 무결성, 비용·수량·시간의 범위, 해금 조건을 로딩 경계에서 검사한다. 밸런스 값은 콘텐츠 데이터에 두고 중복된 원본을 만들지 않는다.

저장에는 `schemaVersion`, 진행 상태, 적용한 실제 시각, 난수 상태, 미완료 활동·전투와 필요한 사건 순서를 포함한다. 세부 필드명과 현재 버전은 첫 저장 구현에서 정의한다. 저장소 키와 내보내기 형식은 이 게임 전용으로 정한다.

새 저장은 검증한 뒤 적용하고, 마이그레이션 실패·손상·지원하지 않는 미래 버전은 원본을 보존한 상태로 알린다. 브라우저 저장의 원자성 범위 안에서 마지막 정상본 복구를 설계한다. 자동 신규 게임 생성으로 손상된 저장을 덮어쓰지 않는다. 불러오기와 오프라인 계산이 중복 실행되어도 같은 보상이 두 번 적용되지 않도록 복귀 처리의 완료 기준을 둔다.

Township 확장의 저장 버전은 3이며 기존 저장을 발견하기 위해 전용 키 `northward-idle.save.v2`는 유지한다. 게임 식별자·버전·적용한 실제 시각·상태·미확인 복귀 요약·작성 창 ID·내용 검사값을 한 객체로 저장한다. 검사값은 우발적 손상 감지용이며 보안 서명이 아니다. v1/v2 형식은 기존 활동·전투·난수·예약 재료를 보존하고 새 마을·농사·수집 상태를 채우는 변환 경로를 갖는다. v2 검사값은 변환 전에 확인하고 원본을 별도 보존한다. v1은 호환 검증용 이전 형식이다. 세부 계약은 [모듈 계약](IMPLEMENTATION_CONTRACT.md)을 따른다.

쓰기 전에 직전 저장을 `.backup`에, 가져오기·초기화·마이그레이션 전에 원본을 `.original`에 보관한다. 알 수 없는 ID·음수 자원·잘못된 시간·전투·예약 재료는 불러오기에서 거부한다. 오류가 나면 진행과 자동 저장을 차단하고 원본·복구 선택을 제공한다. 저장 공간 오류는 알려주고 내보내기를 제공한다.

복귀는 저장 상태 복사본을 최대 7일의 정확한 사건 단위로 계산한 뒤 적용 시각·상태·미확인 요약을 함께 저장한다. 긴 계산은 5분 단위로 브라우저 실행권을 돌려주고 평균 보상으로 대체하지 않는다. 실제 시각이 뒤로 가면 마지막 적용 시각을 유지한다. Web Locks로 한 창만 진행하며, 지원하지 않는 브라우저에서는 저장 변경 사건을 감지해 다른 창의 진행을 멈춘다.

## 변화와 검증

사용자가 결정한 핵심을 바꾸지 않는 내부 경계와 도구 선택은 실행자가 개선할 수 있다. 규모가 작을 때 범용 플러그인 시스템이나 과한 추상화를 먼저 만들지 않는다. 로직·저장·UI의 필요한 검증은 [검증 기준](VALIDATION.md)을 따른다.
