# 시뮬레이션과 저장 구현

[기술 기준](../../../docs/engineering/ARCHITECTURE.md), [현재 기획](../../../docs/design/GAME_DESIGN.md), [진행 상태](../../../docs/PROJECT_STATUS.md)를 읽고 실제 구현 위치를 확인한다. 문서에 제시한 예정 경로를 이미 존재하는 코드로 가정하지 않는다.

## 구현 순서

1. 바꾸려는 활동·전투·저장 상태와 외부 입력을 정한다. 규칙이 사용자 확정인지 실행자 결정인지 확인하고 위임 범위의 빈칸은 구체화한다.
2. 상태 전이와 시간 경계를 구현한다. 자원 소비·보상·해금·승패를 UI 콜백이나 전역 시각·난수에 넣지 않는다. 시간과 난수를 주입하고 미완료 상태를 보존한다.
3. 온라인과 복귀 계산이 같은 핵심 함수를 호출하게 한다. 숨겨진 탭이나 다른 화면에서 별도 전투 공식·보상 배율을 사용하지 않는다.
4. 동일 시각 사건의 순서를 명시한다. 습격·작업 완료·보급 소진·귀환의 순서를 구간 크기나 프레임 수에 맡기지 않는다.
5. Focus Stop의 시간은 엔진이 결정한다. 화면의 애니메이션이 끝나야 실제 공격·보상이 진행되는 연결을 만들지 않는다. 관전과 비관전의 난수 소비 순서도 같게 한다.
6. 수비 중단·회복·재개를 명시적인 상태로 다룬다. 같은 보상을 다시 지급하거나 중단된 작업을 새 작업으로 초기화하지 않는다.

## 데이터와 저장

- JSON의 안정적인 ID와 참조를 검사한다. 레시피·지역·적 수치는 데이터에 두고, 표시 이름으로 상태를 연결하지 않는다.
- 저장 변경은 현재 버전, 이전 저장의 변환, 손상·미래 버전 처리까지 완성한다. 마이그레이션 전 원본을 보존하고 이 게임 전용 저장소 키를 사용한다.
- 복귀 계산을 완료한 시각과 상태를 함께 적용한다. 재로드·재시도에서 시간이나 보상이 중복 반영되지 않게 한다.
- 긴 경과 시간 계산의 최적화는 실제 병목을 측정한 뒤 한다. 사건을 묶을 때 해금·보급 소진·습격·승패·손실 한도를 건너뛰지 않는다.

## 검증과 기록

[검증 기준](../../../docs/engineering/VALIDATION.md)에 따라 변경된 로직의 경계와 온라인·오프라인 일치를 확인한다. 실행할 수 있는 코드·데이터·테스트를 함께 완성하고 실제 수행 결과를 남긴다. 중요한 기술 선택은 [결정 기록](../../../docs/DECISIONS.md), 구현한 기능과 다음 작업은 진행 상태에 갱신한다.
