# 신작 에셋 제작과 적용

[현재 기획](../../../docs/design/GAME_DESIGN.md)과 [화면 기준](../../../docs/design/UI_DIRECTION.md)을 읽는다. 이미 에셋·출처 기록·아트 기준이 있으면 먼저 확인하고 이어간다. 지금 단계에는 선택한 초상 화풍이나 완성 에셋이 없으므로 이를 확정된 것으로 말하지 않는다.

## 제작 순서

1. 실제 사용 위치와 필요한 크기·비율·투명도·여백을 확인한다. 초상, 배경, 작은 아이콘을 하나의 캔버스 규칙으로 처리하지 않는다.
2. 사용자가 핵심 화풍을 정했다면 따른다. 그렇지 않으면 첫 화면에 필요한 최소 에셋으로 일관된 초안을 만들고 실행자 제안으로 기록한다. 에셋 개수를 불필요하게 늘리지 않는다.
3. 북방 환경, 파란색 화면과의 대비, 주인공 한 명이라는 기획을 반영한다. 기존 게임의 파티 구성·죄악별 초상 규칙·색상 체계를 자동 이식하지 않는다.
4. 기존 이미지를 수정하려면 먼저 이미지를 확인한다. 사용할 수 있는 이미지 생성 도구와 해당 이미지 생성 스킬의 지침을 따른다. 기존 SVG·CSS·코드로 만든 아이콘은 적합한 원본 형식으로 수정한다.
5. 생성·수정 결과를 실제 게임 크기와 배경 위에서 확인한다. 가독성, 가장자리, 자르기, 투명도, 축소 시 식별성을 점검한다.

## 저장과 적용

- 논리적인 에셋 ID, 역할, 원본·파생 경로, 크기·형식, 생성 방법·프롬프트 또는 출처, 수정 이력을 기록한다. 수량이 늘면 `assets/manifest.json` 같은 기계 판독 가능한 목록을 도입한다.
- 게임에는 실제 필요한 표시용 파생본을 적용하고 원본도 보존한다. 포맷 변환은 화질과 용량을 확인한 뒤 수행한다.
- 참고작의 초상·아이콘·배경을 새 게임용 에셋으로 직접 복사하지 않는다. 참고 이미지와 실제 사용 권한이 확인된 에셋을 구분한다.
- 사용자가 변형안 비교나 후보만 요청했다면 그 결과를 준비한다. 적용까지 요청했다면 코드와 화면에서 참조를 바꾸고 실제 표시를 확인한다.
- 실제 생성을 수행하지 못했다면 프롬프트 작성과 생성 완료를 구분해 보고한다. 선택한 화풍과 적용 결과는 관련 문서와 진행 상태에 기록한다.
