# 화면과 관전 구현

[화면 기준](../../../docs/design/UI_DIRECTION.md), [현재 기획](../../../docs/design/GAME_DESIGN.md), [기술 기준](../../../docs/engineering/ARCHITECTURE.md)의 화면 경계를 읽는다. 실제 코드와 실행 방법은 [진행 상태](../../../docs/PROJECT_STATUS.md)와 루트 README에서 확인한다.

## 화면 제작

1. 요청에 필요한 실제 흐름을 완성한다. 처음 진입 → 현재 활동 확인 → 조건과 소비 확인 → 활동 선택 → 결과 확인을 연결한다. 의미 없는 버튼이나 목업 값을 동작하는 기능처럼 남기지 않는다.
2. 파란색 기본 바탕과 북방 분위기를 유지한다. 세부 색상과 배치는 판단해 정하되 텍스트·게이지·경고가 읽히는 명암을 확보한다.
3. 메뉴를 이동해도 탐험·채집·수비 상태는 앱의 시뮬레이션에 유지한다. 메뉴 컴포넌트의 생성·제거가 활동 시작이나 종료 명령이 되어서는 안 된다.
4. 화면 입력은 명령을 보내고, 화면은 결과 상태와 사건을 읽는다. 화면용 숫자를 보상·보급·체력의 별도 원본으로 만들지 않는다.

## Focus Stop과 복귀 요약

- 전투 사건의 시각에 맞춰 행동자의 전진·짧은 멈춤·타격·복귀를 연출한다. 렌더링이나 애니메이션 종료가 엔진 시각을 진행시키지 않는다.
- 비관전 중 누적된 공격을 모두 재생해서 현재 상태가 늦게 보이게 하지 않는다. 실시간 사건 재생과 복귀 요약을 분리한다.
- 연출 감소·건너뛰기·프레임 저하는 표시만 바꾼다. 실제 전투 시간·보상·난수는 동일해야 한다.
- 복귀 요약에는 실제 계산 결과만 표시한다. 습격 수, 수비 승패, 소비·손실·전리품과 중단을 구분하고 다음 준비 행동으로 연결한다.

## 실제 확인

브라우저에서 활동을 시작하고 다른 메뉴를 돌아본 뒤 진행 상태를 확인한다. 창 크기 변경, 키보드 조작, 동작 감소, 재접속 요약을 변경 범위에 맞게 확인한다. 데이터가 없어서 만든 샘플 화면은 샘플임을 표시하고 실제 검증과 구분한다. [검증 기준](../../../docs/engineering/VALIDATION.md)에 따른 결과와 실제 제약을 진행 상태에 남긴다.
