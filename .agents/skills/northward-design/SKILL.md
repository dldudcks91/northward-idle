# 기획과 결정 기록

저장소 루트의 [현재 기획](../../../docs/design/GAME_DESIGN.md)과 [진행 상태](../../../docs/PROJECT_STATUS.md)를 먼저 읽는다. 과거 합의의 맥락은 [대화 기록](../../../docs/design/DISCUSSION_LOG.md), 실행자가 정한 세부 기준은 [결정 기록](../../../docs/DECISIONS.md)에서 확인한다.

## 대화와 설계

1. 사용자가 정하려는 선택과 이미 합의한 방향을 구분한다. 이전 제안을 새로운 사용자 확정으로 읽지 않는다. 중요한 선택은 플레이어가 무엇을 준비하고 어떤 결과를 겪는지 설명한다.
2. 핵심 방향을 바꾸는 선택만 함께 정한다. 이름·수치·개별 자원·레시피·화면 배치 같은 위임된 세부안은 판단해 초안을 만들고 기록한다. 설계가 비어 있다는 이유만으로 모든 항목을 질문하지 않는다.
3. 채집 → 제작·보급 → 탐험·수비 → 새로운 자원·성장의 연결을 실제 첫 지역의 활동으로 설명한다. 방치 시간, 플레이어의 준비 선택, 막혔을 때 해결 경로를 함께 정한다.
4. 오프라인 탐험과 오프라인 수비를 구분한다. 오프라인 수비는 확정이고, 탐험 범위는 현재 문서의 미정 상태를 따른다. 해당 정책을 정하기 전에는 수비·제작 등 독립적인 설계를 진행할 수 있다.
5. 수비에서 활동이 중단된다면 중단 조건·주인공 위치·소비 보급·패배 손실·회복·재개의 전이를 끝까지 설명한다. 한 명의 주인공이 동시에 탐험과 수비를 수행하는 모순을 남기지 않는다.
6. 새 시스템마다 반복 작업을 추가하는 대신 어떤 선택이나 성장의 보람을 만드는지 확인한다. 야영지 이사와 재건을 지역 진행의 반복 비용으로 확대하지 않는다.

## 기록과 전달

- 합의가 생기면 현재 기획 본문과 대화 기록을 함께 갱신한다. 핵심 변경은 이전 방향을 대체했음을 남긴다.
- 위임받아 선택한 세부안은 결정 기록에 실행자 결정으로 남긴다. 아직 구현하지 않은 안은 구현 완료로 표시하지 않는다.
- 숫자는 의도와 경계를 정한 뒤 데이터 초안으로 만든다. 정확한 수치가 필요할 때만 근거·단위를 제시한다.
- 참고작의 현재 사실이 필요하면 [참고 안내](../../../docs/reference/README.md)를 확인하고 필요한 원문을 검증한다. 조사 자료의 수치와 신작의 설계값을 구분해서 기록한다.
- 이번 대화에서 정한 것, 미정인 핵심, 실행자가 이어서 진행할 작업을 짧게 연결한다. 상태가 바뀌면 진행 상태 문서를 갱신한다.
