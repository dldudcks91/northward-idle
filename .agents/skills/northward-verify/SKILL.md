# 재현과 검증

[검증 기준](../../../docs/engineering/VALIDATION.md), [현재 기획](../../../docs/design/GAME_DESIGN.md), [진행 상태](../../../docs/PROJECT_STATUS.md)를 읽고 검증하려는 코드와 실행 도구가 실제로 있는지 확인한다.

## 작업 절차

1. 증상·기대 결과·시작 상태·데이터·시드·명령·경과 시간을 정리해 재현한다. 테스트가 통과했다는 사실만으로 실제 증상이 사라졌다고 단정하지 않는다.
2. 바뀐 규칙의 실제 성질을 검사한다. 구현의 줄이나 내부 호출 횟수를 그대로 복제한 테스트 대신 소비·보상·전이·보존 규칙을 확인한다.
3. 시간 로직은 긴 한 구간과 여러 작은 구간, 온라인과 허용된 오프라인 활동을 비교한다. 이벤트 경계 직전·같은 시각·직후를 포함한다.
4. 수비는 중단한 활동, 보급 소진, 패배 뒤 회복·재개, 누적 손실과 장기 부재를 확인한다. 성공 사례뿐 아니라 준비 부족 상태도 포함한다.
5. 저장은 이전 버전·손상·미래 버전·미완료 전투·복귀 중 재로드를 다룬다. 원본 보존과 중복 보상 방지를 확인한다.
6. 화면과 Focus Stop은 실제 브라우저에서 확인한다. 엔진 비교와 관전 화면 확인을 구분하고, 다른 화면·숨겨진 탭·동작 감소에서도 진행 결과가 같아야 한다.

## 밸런스와 성능

첫 지역의 준비 → 탐험 → 수비 → 개선 흐름을 측정한다. 음식 수급, 작업 중단 비율, 장비 개선의 효과, 다음 지역의 병목을 설명한다. 무작위 결과는 고정 시드 여러 개와 표본 수·편차를 함께 기록한다. 성능 최적화는 실제 계산 시간과 상태 일치 모두 확인한다.

## 결과와 종료

검증한 조건·명령·결과와 남은 재현 제약을 기록한다. 검증하지 못한 항목을 통과로 쓰지 않는다. 관련 검증이 통과하면 새 변경이나 실제 우려가 없는 한 같은 검증을 반복하지 않는다. 준비 문서와 스킬 변경은 루트의 `scripts/validate_workspace.py`를 실행한다. 실행 결과와 수정된 기능을 진행 상태에 갱신한다.
